# 项目结构说明

## 一、文档目的

本文档用于说明当前 Unity 项目的整体结构、主要目录职责、核心脚本分工、场景划分以及当前开发重点，方便后续进行：

- 项目维护
- 功能扩展
- 代码协作
- 问题排查
- 文档整理
- 与 GitHub / Codex 配合开发

---

## 二、项目当前阶段

本项目目前处于 **基础框架搭建与功能整合阶段**。  
当前开发重点是先完成一个可运行、可维护、可扩展的游戏基础框架，再逐步补充剧情、调查玩法、推理内容、美术资源与交互细节。

当前已具备或正在搭建的基础模块包括：

- 主菜单
- 暂停菜单
- 场景切换
- 音频系统
- 对话系统
- 任务系统
- 存档系统
- 调查交互触发

## 三、项目目录结构

当前项目主体目录如下：

```text
Assets
├─ Animations
├─ Art
├─ Audio
├─ Data
├─ Prefabs
├─ Resources
├─ Scenes
├─ Scripts
├─ Settings
└─ StreamingAssets

Packages
ProjectSettings
```

### 目录职责说明

- **Assets**：项目主要资源目录，包含场景、脚本、预制体、美术、音频等内容
- **Packages**：Unity 包管理配置
- **ProjectSettings**：Unity 项目设置文件

---

## 四、Assets 目录说明

### 1. Animations
用于存放角色动画、UI 动画或其他可复用动画资源。

### 2. Art
用于存放美术资源，例如：
- 场景图
- 像素素材
- UI 图片
- 图标
- 角色贴图

### 3. Audio
用于存放音频资源，例如：
- BGM
- SFX
- 按钮音效
- 环境音

### 4. Data
用于存放项目中的数据资源，例如：
- 配置数据
- ScriptableObject
- 任务数据
- 对话数据  
  （当前可根据后续需求继续细化）

### 5. Prefabs
用于存放预制体资源，例如：
- UI 预制体
- 玩家预制体
- 交互物预制体
- 存档槽预制体

### 6. Resources
用于存放需要通过 `Resources.Load` 动态加载的资源。  
后续应谨慎使用，避免无序堆积。

### 7. Scenes
用于存放项目场景文件。

### 8. Scripts
用于存放项目中的全部脚本逻辑，是当前框架的核心目录。

### 9. Settings
用于存放项目相关设置资源或渲染/配置相关内容。

### 10. StreamingAssets
用于存放运行时需要原样读取的资源文件。

## 六、核心脚本职责表

### 数据类

#### GameTaskData
任务数据结构，用于保存任务相关信息，例如：
- 任务标题
- 任务描述
- 任务状态
- 后续扩展字段

#### DialogueLine
对话数据结构，用于描述单条对话内容，例如：
- 说话人
- 对话文本
- 其他扩展字段

#### SaveData
存档数据结构，用于保存游戏运行过程中的关键进度信息。

---

### 管理器类

#### AudioManager
负责全局音频控制，包括：
- BGM 播放
- SFX 播放
- 音量数据维护
- 与音频设置 UI 的联动

#### DialogueManager
负责全局对话流程控制，包括：
- 对话开启
- 对话推进
- 对话结束
- 对话显示面板联动

#### GameManager
负责全局游戏状态与流程控制。  
后续可继续承担：
- 场景初始化状态
- 全局流程切换
- 总体运行状态管理

#### SaveManager
负责存档系统管理，包括：
- 保存
- 读取
- 存档槽逻辑对接
- 继续游戏逻辑支持

#### TaskManager
负责任务系统状态管理，包括：
- 添加任务
- 更新任务
- 任务状态切换
- 与任务 UI 联动

#### PauseManagerrScript
负责暂停状态控制。  
当前命名存在一定不规范之处，后续可考虑统一整理为：
- `PauseManager`
- 或 `PauseStateManager`

在当前阶段，应优先保持其现有挂载和引用关系稳定。

---

#### MainMenuController
负责主菜单界面逻辑，例如：
- 面板切换
- 按钮响应
- 主菜单显示控制

#### PauseMenuController

- 子面板切换

负责单个存档槽的显示与交互逻辑。

负责任务系统的界面显示与刷新逻辑。

#### UIButtonSound
负责按钮悬停 / 点击时的音效反馈。

#### AudioController
负责音频设置界面逻辑。

#### AudioSettingsBinder
负责音频设置项与底层音频系统之间的绑定逻辑。

#### SceneLoader
负责场景加载入口逻辑。  
通常用于：
- 按钮切场景
- 场景跳转调用

#### MainMenuGameEntry
负责从主菜单进入游戏的流程控制，例如：
- New Game
- Continue
- 进入场景前的数据衔接

---

### 交互 / 玩家相关类

#### InteractionDialogueTrigger
负责交互触发对话逻辑，常用于：
- 玩家进入范围
- 玩家按键触发

## 九、当前已知风险点

基于当前结构，后续开发中需要重点注意以下问题：

### 1. Inspector 绑定风险
Unity 项目中大量逻辑依赖：
- `public` 字段
- `[SerializeField]` 字段
- Button `OnClick`
- 场景对象引用
- 预制体引用

因此在修改脚本时，应尽量避免：
- 随意重命名字段
- 删除按钮调用方法
- 改动脚本挂载对象名称
- 大规模调整预制体结构

---

### 2. 管理器与 UI 职责重叠风险
当前项目中，部分系统可能存在：
- 管理器做了过多 UI 逻辑
- UI 脚本承担了过多系统逻辑

后续应逐步保持职责边界清晰：

- **Manager**：负责状态与流程
- **Controller / UI**：负责界面显示与交互响应

---

### 3. 存档链路风险
存档系统涉及多个脚本联动：

- `SaveManager`
- `SaveData`
- `SaveSlotUI`
- `PlayerSaveLoader`
- `SceneLoader`

后续重点检查：
- Continue 是否能正确恢复数据
- 玩家位置是否正确恢复
- 存档信息是否与实际运行状态一致

---

### 4. 暂停与音频联动风险
暂停系统与音频系统之间存在明显联动关系，后续应重点检查：

- `Time.timeScale`
- BGM 暂停与恢复
- 设置面板的音量同步
- 暂停菜单子面板切换逻辑
